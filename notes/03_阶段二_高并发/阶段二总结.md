## ✅ 验收标准达成情况

### 1. epoll reactor 事件驱动模型 ✅

**实现内容**：
- `EpollReactor` 类（`server/epoll_reactor.h/cpp`）
  - epoll_create1() 创建 epoll 实例
  - 边缘触发模式（EPOLLET）
  - 事件循环（epoll_wait）
  - 事件处理器回调机制
- 监听 socket 和客户端 socket 统一管理
- 非阻塞 I/O

**技术特点**：
- 边缘触发（ET）+ 非阻塞 I/O
- 单线程事件循环，避免竞态条件
- Lambda 回调，灵活处理不同类型事件

### 2. 线程池：任务队列 + worker + 优雅关闭 ✅

**实现内容**：
- `ThreadPool` 类（`utils/thread_pool.h/cpp`）
  - 任务队列（std::queue）
  - Worker 线程（std::thread）
  - 任务提交（submit）返回 std::future
  - 优雅关闭（shutdown）等待任务完成
- 线程安全（mutex + condition_variable）
- 异常处理（捕获任务执行异常）

**技术特点**：
- 使用 std::packaged_task 封装任务
- 返回 std::future 支持异步结果
- 条件变量实现线程睡眠/唤醒
- 优雅关闭：不接受新任务，完成现有任务

### 3. 过载保护：超时/限流/拒绝策略 ✅

**实现内容**：
- `ConnectionManager` 类（`server/connection_manager.h/cpp`）
  - 连接数限制（默认 10000）
  - 连接超时检测（默认 60 秒）
  - 请求数限制（每连接最大 10000 请求）
  - 拒绝策略（达到上限拒绝新连接）
- 超时检查线程（每 10 秒检查一次）
- 统计信息（拒绝连接数、当前连接数）

**技术特点**：
- 连接活跃时间追踪
- 自动清理超时连接
- 防止资源耗尽

## 🎯 技术亮点

### 1. epoll + 非阻塞 I/O

**架构**：
```
┌─────────────────────────────────────┐
│      EpollReactor (事件循环)        │
│  ┌─────────────────────────────┐   │
│  │  epoll_wait()               │   │
│  │  ├─ Listen Socket (EPOLLIN) │   │
│  │  ├─ Client Socket 1         │   │
│  │  ├─ Client Socket 2         │   │
│  │  └─ Client Socket ...       │   │
│  └─────────────────────────────┘   │
└─────────────────────────────────────┘
         │
         ├─→ handleListenEvent()  ──→ accept() 循环
         └─→ handleClientEvent()  ──→ 提交到线程池
```

**优势**：
- 单线程管理所有连接（无锁）
- 边缘触发避免重复通知
- 非阻塞 I/O 避免阻塞整个循环

### 2. 线程池 + 任务队列

**架构**：
```
┌────────────────────────────────────┐
│         ThreadPool                 │
│  ┌──────────────────────────┐     │
│  │  Task Queue              │     │
│  │  ┌────┬────┬────┬────┐  │     │
│  │  │Task│Task│Task│... │  │     │
│  │  └────┴────┴────┴────┘  │     │
│  └──────────────────────────┘     │
│          │                         │
│  ┌───────┴────────┐               │
│  │ Worker Threads │               │
│  ├─ Thread 1      │               │
│  ├─ Thread 2      │               │
│  ├─ Thread 3      │               │
│  └─ Thread ...    │               │
│  └────────────────┘               │
└────────────────────────────────────┘
```

**优势**：
- 避免频繁创建/销毁线程
- 任务队列缓冲突发请求
- 线程数可配置（默认 = CPU 核心数）

### 3. 连接管理 + 过载保护

**保护机制**：
1. **连接数限制**：拒绝超过 10000 个连接
2. **连接超时**：自动关闭 60 秒无活动连接
3. **请求数限制**：单连接最多处理 10000 请求
4. **后台清理**：超时检查线程定期清理

**防止**：
- 连接耗尽
- 慢速攻击（Slowloris）
- 资源泄漏

## 🚀 使用方法

### 启动服务器

```bash
# 使用默认线程数（= CPU 核心数）
./build/bin/ChatGPTServer 8080

# 指定线程数
./build/bin/ChatGPTServer 8080 4

# 指定端口和线程数
./scripts/run.sh 9000 8
```

### 运行压测

```bash
# Python 压测（推荐）
python3 scripts/simple_benchmark.py

# Shell 压测（需要 ab 或 wrk）
./scripts/benchmark.sh

# 自定义压测
# 修改 simple_benchmark.py 中的配置：
#   CONCURRENCY = 200
#   TOTAL_REQUESTS = 20000
```

### 监控服务器

```bash
# 查看日志
tail -f logs/server.log

# 查看连接数（在代码中添加 /stats 端点）
curl http://localhost:8080/stats
```
